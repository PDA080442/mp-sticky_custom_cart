# QA: переход в оформление заказа из sticky и согласованность корзины

Плагин не подменяет сессию WooCommerce: корзина — это `WC()->cart` и стандартные cookie Woo. Sticky только отображает снимок через AJAX и синхронизирует UI по событиям Woo.

Связанные документы: **`docs/qa-cart-route.md`** (редирект `/cart/`), **`docs/qa-external-cart-links.md`** (UTM, `add-to-cart`).

## 1. Прямой переход из sticky в checkout

**Ожидание:** при непустой корзине кнопка «Оформить заказ» ведёт на URL checkout Woo (`wc_get_checkout_url()`), с учётом разрешённых query-параметров текущей страницы (см. `CheckoutQueryPreserve` / `checkoutPreserveQueryKeys` в `mpSccData`).

**Проверка:**

1. Добавьте товар в корзину (каталог или карточка).
2. В нижней панели нажмите «Оформить заказ».
3. Открывается страница оформления WooCommerce; целевой URL формируется как `wc_get_checkout_url()` и совпадает с **WooCommerce → Настройки → Дополнительно → Страница оформления заказа** (или эквивалент в мультиязычном магазине).

**Регрессия в коде:** `tests/checkout-navigation-smoke.test.js`.

## 2. Актуальный состав корзины на checkout

**Ожидание:** позиции и суммы на checkout совпадают с тем, что было в sticky/drawer до перехода (одна сессия Woo).

**Проверка:**

1. Добавьте 2 разных товара (или измените количество в drawer).
2. Убедитесь, что summary в sticky совпадает с ожиданием.
3. Перейдите в checkout — состав заказа должен совпадать (те же позиции и количества).

Если после AJAX-операций сомнения — обновите страницу каталога и снова откройте checkout: данные должны совпасть с серверной корзиной.

## 3. Пустая корзина

**Ожидание:** кнопка checkout визуально неактивна, `href="#"`, клик и активация с клавиатуры не уводят на checkout (`mp-scc-checkout--disabled`).

**Проверка:**

1. Очистите корзину (кнопка «Очистить» или удаление позиций).
2. Кнопка «Оформить заказ» не должна вести на checkout при клике.
3. При необходимости откройте checkout напрямую по URL — Woo покажет пустую корзину / сообщение по правилам темы (это поведение Woo, не плагина).

## 4. Обновление вкладки checkout (F5)

**Ожидание:** после полного обновления страницы checkout Woo пересчитывает корзину из сессии; состав не должен «теряться» без изменения корзины на сервере.

**Проверка:**

1. С непустой корзиной откройте checkout.
2. Нажмите обновление страницы (F5).
3. Состав заказа остаётся тем же (при условии, что сессия не сброшена, нет выхода из аккаунта в другой вкладке и т.д.).

## 5. Возврат назад в каталог

**Ожидание:** кнопка «Назад» браузера с checkout возвращает на предыдущую страницу; sticky на каталоге подхватывает актуальную корзину (события Woo / `refresh()`).

**Проверка:**

1. С каталога перейдите в checkout.
2. Нажмите «Назад».
3. Счётчик и сумма в sticky соответствуют корзине (при расхождении — см. п. 6).

## 6. Cookie / session целостность

**Ожидание:** плагин использует те же механизмы Woo, что и остальной магазин. Снимок для UI строится на сервере (`build_cart_snapshot_payload` в `AjaxEndpointsHooks`), поле `snapshot_ts` позволяет отличить свежие ответы.

**Проверка:**

1. В одной сессии гостя: добавление → checkout → изменение в другой вкладке не требуется для базового сценария.
2. При подозрении на рассинхрон: откройте инструменты разработчика → Application → Cookies и убедитесь, что присутствуют cookie Woo для домена (имена зависят от версии Woo/хостинга).
