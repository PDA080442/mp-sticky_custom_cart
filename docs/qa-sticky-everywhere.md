# QA: sticky «везде» (регрессионный набор)

Цель: убедиться, что нижняя панель корзины (`#mp-scc-sticky-root`) ведёт себя предсказуемо на типовых шаблонах WordPress / WooCommerce.  
Правило по умолчанию в коде: **`StickyCartVisibility::should_render_sticky()`** возвращает `true` для фронта с корзиной Woo, **кроме** пустой корзины при включённом по умолчанию флаге **`sticky_hide_when_empty_enabled`** (shell появляется после первого добавления в корзину). Исключения — отключённая sticky, feed/embed, отсутствие `WC()->cart`, админка. Дополнительно можно отключить вывод фильтром **`mp_sticky_custom_cart_should_render_sticky`**.

На каждой странице проверяйте:

- [ ] В DOM есть `#mp-scc-sticky-root` (если ожидается показ).
- [ ] У `body` есть класс **`mp-scc-sticky-active`** при активной панели.
- [ ] Нет неконтролируемого наложения на критичный контент (см. `docs/qa-sticky-visibility.md` про отступ и CLS).

---

## 1. Архив товаров (shop, категории, теги)

**Контекст:** `is_shop()`, `is_product_category()`, `is_product_tag()` и кастомные таксономии товаров.

- [ ] Sticky видна; добавление из каталога / карточки обновляет счётчик и drawer.
- [ ] Фильтры/сортировка темы не ломают `position: fixed` у панели (см. overflow в `qa-sticky-visibility`).

## 2. Single product

**Контекст:** `is_product()`.

- [ ] Sticky видна; вариативный товар — сценарии из `docs/qa-variable-products.md`.
- [ ] После AJAX add срабатывает обновление sticky (события Woo + snapshot).

## 3. Статические страницы

**Контекст:** `is_page()` (О компании, контакты, политика и т.д.), без специального шаблона Woo.

- [ ] Sticky отображается, если WooCommerce загружен и корзина доступна (типичный витринный сайт).
- [ ] Контент страницы читаем с учётом `body.mp-scc-sticky-active` и нижнего резерва.

## 4. Блог: архив записей и одиночная запись

**Контекст:** `is_home()` (блог на главной), `is_archive()` для постов, `is_singular('post')`.

- [ ] Sticky видна на списке постов и в одиночной записи.
- [ ] Комментарии / подвал записи не перекрыты полосой при прокрутке вниз.

## 5. Оформление заказа (checkout)

**Контекст:** `is_checkout()` (и thank you / pay, если тема открывает их отдельно).

- [ ] **UI:** панель не дублирует и не перекрывает поля оформления, кнопки оплаты, юридические чекбоксы. При конфликте — скрыть sticky на checkout через фильтр:

```php
add_filter( 'mp_sticky_custom_cart_should_render_sticky', function ( $show ) {
	if ( function_exists( 'is_checkout' ) && is_checkout() && ! is_order_received_page() ) {
		return false;
	}
	return $show;
} );
```

- [ ] При необходимости скорректировать z-index модалок оплаты в теме.

## 6. Личный кабинет (My Account)

**Контекст:** `is_account_page()`.

- [ ] Sticky видна на разделах аккаунта (заказы, адреса, данные).
- [ ] Навигация аккаунта и формы не перекрыты; при узкой сетке темы — проверить мобильную вёрстку.

## 7. Кастомные шаблоны и конструкторы

**Контекст:** полноширинные лендинги, шаблоны Elementor / WPBakery / блоков FSE, страницы с отдельным `header.php`.

- [ ] `#mp-scc-sticky-root` выводится в **`wp_footer`** (как в плагине), а не внутри колонки с `transform`, иначе `fixed` может «прилипнуть» к контейнеру.
- [ ] Canvas-шаблоны без `body` классов темы: проверить наличие `mp-scc-sticky-active` и резерва по высоте.

## 8. Корзина WooCommerce

**Контекст:** `is_cart()`.

- [ ] Sticky согласована с основной таблицей корзины (дублирование CTA допустимо по продукту; при необходимости скрыть через тот же фильтр).
