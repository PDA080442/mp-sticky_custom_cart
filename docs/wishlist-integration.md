# Wishlist + каталог: ограничения интеграции

Плагин **не вставляет** свою иконку избранного и **не дублирует** разметку сторонних плагинов. Интеграция сводится к:

1. **Слоистость (z-index)** — кнопка «Подробнее» (`--mp-scc-catalog-overlay-z-index`, по умолчанию 4) остаётся **ниже** типичных контейнеров wishlist (`--mp-scc-wishlist-icon-z-index`, по умолчанию 6), если включён флаг **«Интеграция heart-иконки»** и на `body` добавлен класс `mp-scc-wishlist-integration-on` (делает storefront JS).

2. **Зона клика** — горизонтальный зазор между полосой «Подробнее» и правым краем задаётся отступами сердечка и полем «Зазор overlay от сердечка» (`--mp-scc-wishlist-overlay-clearance` и связанные переменные в `assets/css/frontend.css`).

3. **Визуальные состояния** — стили `:hover` / `:active` wishlist **не переопределяются**; в CSS задаются только `position: relative`, `z-index` и `pointer-events: auto` для известных селекторов (YITH, TI WooCommerce Wishlist, WPC Smart Wishlist и т.д.).

4. **Фокус с клавиатуры** — для ссылки «Подробнее» добавлен видимый `outline` при `:focus-visible`. Порядок табуляции определяется темой и порядком узлов в DOM; плагин не меняет `tabindex` у сторонних кнопок.

5. **Дубликаты в карточке** — если в одной `li.product` оказывается несколько кнопок wishlist, это ошибка темы/плагина. Для диагностики откройте каталог с `?mp_scc_wishlist_debug=1` в URL и смотрите предупреждения в консоли.

6. **Расширение селекторов** — при нестандартном плагине добавьте в дочернюю тему узкие правила `z-index` для своего селектора или используйте фильтр WordPress для данных storefront (при необходимости — отдельный мини-патч в теме).

Рекомендуется: **z-index избранного > z-index overlay** (настраивается в админке: Каталог → Z-index слоя «Подробнее», Избранное → Z-index иконки).
